# Исходный сценарий этапа 0

Это наши открытые сценарии, не официальный TPC/YCSB результат.

Перед публикацией в сохраненных выводах заменен только локальный путь к рабочей папке на `<workspace>`. Числа и checksums исходных SQL/скриптов не изменены; оригинальные выводы сохранены локально в игнорируемом artifacts/publication-originals.

## Что находится в папке

- `schema.sql`: товары, пользователи, заказы, позиции и журнал изменения остатка.
- `read.pgbench`: чтение карточки по ключу, применяется для короткого прогрева.
- `mixed.pgbench`: 95% чтений / 5% атомарных обновлений остатка и событий.
- `verify.sql`: исходные проверки диапазонов и внешних ссылок.

## Воспроизводимый безопасный запуск

Требуется установленный PostgreSQL с initdb, pg_ctl, psql, createdb и pgbench, а также Python 3 для вспомогательного запуска. Наше ядро будет на Rust.

Из корня проекта:

```sh
python3 tools/run_stage0_baseline.py --output artifacts/stage0-baseline-new
```

Скрипт инициализирует отдельный временный кластер, отключает TCP, использует Unix socket в приватном каталоге и запускает только свои новые тестовые базы. Локальные существующие экземпляры PostgreSQL не используются. Каталог результата должен быть новым; предыдущие результаты не перезаписываются.

После окончания временный сервер останавливается и его данные удаляются. Сырые отчеты и `summary.json` остаются в указанном каталоге. Если сервер не удалось остановить, файлы сохраняются для ручной диагностики.

По умолчанию: 100 000 товаров с описанием 128 байт, 10 000 пользователей, клиенты 1 и 8, три пятисекундных прогона каждого режима. Каждый прогон начинается с новой базы; прогрев только читает. `fsync`, `synchronous_commit`, `full_page_writes` включены, isolation — serializable. Prepared protocol; для конфликтующей транзакции допускается до пяти попыток, число повторов сохраняется.

Режим большей базы, соответствующий размеру основного продуктового профиля:

```sh
python3 tools/run_stage0_baseline.py --products 1000000 --users 100000 --payload-bytes 1024 --seconds 30 --output artifacts/stage0-larger
```

Этот режим занимает больше диска и времени. Даже 30 секунд не являются финальным соревнованием; длительность финальных прогонов определяется BENCHMARKS.md.

## Что можно заключить из исходного запуска

SQL-схема и сценарий выполняются на проверенной версии PostgreSQL; есть фактический локальный throughput и средняя задержка, а инварианты данных не нарушились. Такой запуск помогает подготовить наше дальнейшее сравнение.

## Что он пока не доказывает

Короткие прогоны на macOS, небольшие данные и работающие сторонние процессы не доказывают производственную производительность, p99, сохранность при потере питания, преимущества нашей еще не написанной базы или первое место среди конкурентов. Установленный PostgreSQL 18.0 — локальная исходная точка; финальные сравнения используют актуальные исправленные версии и закрепленную production-среду.

Полное время повторов отражается в показателях pgbench, но полноценная p99 прикладной операции потребует отдельного фиксируемого измерения в финальном harness. Отдельные первичные прогоны с ошибкой сохраняются и не считаются успешными.
