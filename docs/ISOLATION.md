# Изоляция и сессии

Дата: 9 октября 2026 года. Реализация этапа 4, окончательная приемка — в [отчете](milestones/04.md). Это API локальных сессий; SQL появляется на этапе 5, а сетевое соединение на этапе 6 использует ту же сессию.

## Порядок транзакций

Одна глобальная справедливая читательско-писательская блокировка на базу. Читающие транзакции удерживают shared permit, читающие-пишущие — exclusive permit весь срок транзакции. Все изменяемые ключи, metadata и будущие каталог/индексы относятся к одному private write set. Отдельного обходного пути записи у клиента нет.

Клиенты видят последовательную историю: писатель исключает читателей и других писателей, совместные читатели видят одно неизменяемое состояние. Писатель читает собственные изменения. Новые читатели не обходят ожидающего писателя; подряд стоящие в очереди читатели могут получать доступ совместно. При завершении COMMIT/ROLLBACK ресурсы освобождаются перед ответом. Успешная запись следует [DURABILITY.md](DURABILITY.md).

READ ONLY запрещает insert/update/delete и повышение до READ WRITE. Для записи нужна новая транзакция после окончания читающей. Так исключается deadlock повышения блокировки. Снимков MVCC и параллельных писателей в этой версии нет.

Autocommit выполняет одну операцию: чтение под shared permit без WAL, запись под exclusive permit с устойчивым commit. Явные BEGIN/COMMIT/ROLLBACK доступны через Session API. ROLLBACK в idle безопасен, COMMIT в idle дает KD4006.

## Ошибки, отмена и отключение

Ошибка команды в явной транзакции переводит ее в aborted. Дальнейшие команды получают KD4001 до ROLLBACK. Ошибка parser/type resolver должна передаваться через Session.fail, а не обходить это правило. COMMIT aborted не публикует частичные изменения и возвращает ошибку. Обычная aborted транзакция сохраняет блокировку до завершения или таймаута.

При отмене, максимальном времени жизни, idle timeout или disconnect private write set откатывается и блокировки освобождаются без следующей команды клиента. После отмены/timeout сессия остается aborted, но уже не держит блокировку; первая следующая команда получает причину отказа, если она еще не была сообщена, затем KD4001. ROLLBACK очищает это состояние.

Отмена проверяется между командами, на доступе к страницам (включая cache hits) и непосредственно перед append WAL. После начала commit WAL операция доходит до устойчивого завершения или KD3002/poison; отмена не означает откат уже устойчивого commit. Сетевая отмена и проверка ключа сессии добавляются на этапе 6.

Для ожидания блокировки и молчащего клиента cancellation опрашивается не реже 10 мс. Таймауты не прерывают произвольно зависший системный вызов fsync или scheduler ОС: это граница cooperative cancellation. Завершение процесса в таком случае требует обычного recovery.

## Лимиты

| Параметр | По умолчанию | Допустимая настройка |
|---|---:|---:|
| Сессии | 32 | 1–64 |
| Ожидание блокировки | 5 с | больше 0, максимум 1 час |
| Время жизни транзакции | 30 с | больше 0, максимум 1 час |
| Idle in transaction | 5 с | больше 0, максимум 1 час |
| Приватные страницы писателя | 256 × 16 КиБ | предел ядра; ошибки откатывают весь write set |
| Очередь команд одной сессии | 1 | фиксировано |
| Ключ / значение | 512 байт / 8 КиБ | проверяется до копирования команды |
| Range result | 100 000 строк / 8 МиБ | предел tree API |

У каждого читающего клиента собственный ограниченный кэш с заданным при открытии бюджетом. Адmission limit ограничивает число worker threads/кэшей/ответов; это не абсолютная RSS quota процесса. Логи и SQL history не добавляются без отдельного лимита. Возвращенный результат материализуется и ограничивается внутри движка, поэтому медленный потребитель не держит autocommit lock при передаче ответа.

## Диагностика

KD4001 aborted, KD4002 write in READ ONLY, KD4003 lock timeout, KD4004 cancel, KD4005 lifetime/idle timeout, KD4006 invalid transaction state. Это диагностические коды ядра, их отображение в SQLSTATE определяется на SQL/protocol этапах.

Lock metrics содержат текущих читателей/писателя/очередь, число успешных grants, сумму и максимум времени ожидания успешных grants. Это не полная latency запроса и не p95/p99, отмененные/истекшие ожидания не включены в сумму. Отдельный [concurrency report](milestones/04.md) раскрывает стоимость одного писателя. Новые оптимизации обязаны повторять истории изоляции и crash tests.
