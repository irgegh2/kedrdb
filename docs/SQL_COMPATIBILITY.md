# Матрица SQL: цель 1.0 и текущая локальная реализация

Стадия: начальная реализация этапа 5, полная приемка еще идет. Таблицы и поддерживаемый SQL доступны через локальные `sql`/`sql-stream` и Rust SqlSession. Сетевого сервера пока нет. Таблица ниже сохраняет обязательный состав 1.0; текущая реализация указана после таблицы. «Требуется» не означает принятую production-возможность.

| Возможность | В 1.0 | Условия |
|---|---|---|
| INT / INTEGER | Требуется | Знаковое 32-битное число, ошибка переполнения |
| BIGINT | Требуется | Знаковое 64-битное число, ошибка переполнения |
| TEXT | Требуется | UTF-8, бинарное сравнение, ограниченная длина строки |
| BOOLEAN, NULL | Требуется | SQL-семантика NULL, IS NULL/IS NOT NULL |
| CREATE TABLE / DROP TABLE | Требуется | Постоянный каталог, транзакционное DDL |
| ALTER TABLE ADD COLUMN | Требуется | Начальный вариант: nullable столбец без DEFAULT |
| PRIMARY KEY | Требуется | Один столбец BIGINT, задается приложением |
| NOT NULL / UNIQUE | Требуется | Включая проверку при UPDATE и восстановлении |
| FOREIGN KEY | Требуется | Один столбец BIGINT → BIGINT PK, проверка в конце команды, NO ACTION |
| CREATE INDEX | Требуется | Один столбец; B+ tree |
| INSERT с явными столбцами и VALUES | Требуется | Одна/несколько строк, атомарность команды |
| SELECT, UPDATE, DELETE | Требуется | Проверка имен и типов до исполнения |
| WHERE | Требуется | Сравнения, AND, NULL; OR вне первого состава |
| ORDER BY / LIMIT | Требуется | Один столбец сортировки; согласованные ASC/DESC и NULLS |
| COUNT(*) | Требуется | Без общего набора агрегатов |
| INNER JOIN | Требуется | Начальный вариант — равенство столбцов |
| BEGIN / COMMIT / ROLLBACK | Требуется | SERIALIZABLE-эквивалентная модель; READ ONLY |
| Параметры $1, $2, … | Требуется | Extended protocol, текстовый и необходимый бинарный формат |
| EXPLAIN | Требуется | Реальный выбранный доступ и индекс |
| generate_series, repeat, SQL-конкатенация | Только загрузчик PostgreSQL | Не обязательные функции первого движка |
| JSONB, NUMERIC, TIMESTAMP, UUID | Позже или отдельное расширение состава | Первые прикладные данные обходятся базовыми типами |
| Подзапросы, CTE, оконные функции | Позже | Не объявляются совместимыми |
| SERIAL/IDENTITY, RETURNING, UPSERT, COPY | Отдельное решение по потребности пилота | Пока не обязательны |
| Все pg_catalog и information_schema | Нет полного обещания | Только необходимое выбранному клиенту |
| pgAdmin | Отдельная будущая цель | Нужен большой набор каталоговых запросов |

Начальные реальные проверки выполняются на PostgreSQL, а будущие дифференциальные проверки сравнивают наш движок с PostgreSQL на пересечении диалектов. Данные загрузчика переводятся в обычные INSERT/поток импорта для нашего движка; зависимость от generate_series не добавляется в его SQL.

## Начальная локальная реализация этапа 5

Работают CREATE/DROP TABLE, простой ADD COLUMN, CREATE [UNIQUE] INDEX, INSERT с явным списком столбцов, SELECT/UPDATE/DELETE, COUNT(*), один INNER JOIN, один ORDER BY и LIMIT. Поддерживаются четыре типа, одноколоночные PK/UNIQUE/FK, NOT NULL, AND/сравнения/IS NULL и числовые `+`/`-` с проверкой переполнения. Унарный знак — только перед целочисленным literal. NULL использует трехзначную логику; ASC по умолчанию NULLS LAST, DESC — NULLS FIRST. Имена и типы связываются до чтения, включая пустую таблицу и LIMIT 0.

Параметры `$1..$256` передаются как Value через Rust API; CLI пока принимает SQL без отдельного массива параметров. Quoted identifiers сохраняют регистр, unquoted переводятся в ASCII lower case. Только имена без schema qualification; table aliases требуют AS. Обычные TEXT literals используют удвоенную одинарную кавычку, без backslash escape; TEXT не содержит NUL. Не поддерживаются неявное преобразование строк в числа, collations, casts, DEFAULT/identity, composite keys, OR, дополнительные aggregate/functions, GROUP BY, RETURNING, UPSERT, CTE, подзапросы, views и procedures. Лишние tokens/clauses дают явную ошибку.

Каждой таблице нужен один BIGINT PK, заданный приложением. FK ссылается только на такой PK; self-reference разрешена. NO ACTION не является CASCADE. Foreign keys проверяются на конечном состоянии команды, UNIQUE при изменении индекса. Несколько NULL в UNIQUE допускаются. DDL, строки и indices меняются в том же private write set; ошибка SQL aborts явную транзакцию до ROLLBACK.

EXPLAIN SELECT сообщает реальный PrimaryKeyLookup, IndexLookup или FullScan. Индекс пока используется только для equality/IS NULL, JOIN — потоковый nested loop. ORDER BY не обещает стабильный порядок одинаковых значений: для сравнения нужен уникальный ключ либо multiset; LIMIT через группу равных значений не дает детерминированного выбора строк. COUNT(*) без GROUP BY нельзя смешивать с обычными projection или ORDER BY в первом диалекте.

Лимиты: SQL 64 КиБ, 4096 tokens, 32 уровня вложения, 256 expression nodes; 128 таблиц, 256 columns/indices на table, 63 UTF-8 bytes на identifier, encoded row 8 КиБ. Полный secondary key ≤512 bytes; для TEXT в SQL index остается до 484 UTF-8 bytes. Private write set — максимум 256 pages. На рабочие данные/результат задается бюджет 8 МиБ, с запасом на рост vector capacity; при превышении ошибка вместо неограниченного роста. Большой UPDATE/DELETE или CREATE INDEX может потребовать деления на команды; невыполненная команда откатывается. Штатный key/value каталог автоматически в SQL не преобразуется.

`kedr sql <directory> '<statement>'` выполняет одну команду и выводит JSON. `sql-stream` сохраняет одну сессию и принимает ровно одну полную команду на строке. Пример магазина — [examples/shop.sql](../examples/shop.sql). Приемка и обнаруженные расхождения — [отчет 05](milestones/05.md).

Сетевые клиенты-кандидаты: psql, psycopg 3. Их точные версии и операции будут указаны в клиентской матрице на этапе 6. Работу ORM и графических клиентов заранее не утверждаем.
