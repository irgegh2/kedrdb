# Этап 6: сначала Kedr Studio, затем сервер

Дата: 10 октября 2026 года. Статус: **в работе**. Этап 5 принят в Linux/macOS CI; [отчет](05.md).

Первым реализуется нативное приложение Kedr Studio на Rust: отдельный crate, основное окно, дерево объектов, редактор SQL, таблица результатов, сообщения и состояния. [Направление дизайна](../STUDIO_DESIGN.md). Используется eframe 0.35.0 с glow, закреплено в Cargo.lock.

Текущий транспорт — явно обозначенный предпросмотр интерфейса. Он показывает готовые примеры, имеет ограниченную очередь и отмену. Он не подключается к базе, не читает/меняет ее файлы, не выполняет произвольный SQL и не подтверждает запись. Не засчитывается в серверную приемку.

Локально на macOS ARM64: сборка и Clippy с запретом warnings пройдены, три теста Studio проверяют ограничение очереди/отмену, запрет имитации записи и закрытие фонового обработчика. Настоящее окно запущено; снимки пустого состояния и результатов просмотрены. Найдено и исправлено неполное заполнение пустой панели результатов. Кириллица, типы и отдельное отображение NULL читаются. Снимки находятся в локальном `artifacts/studio-preview`; это не Linux-проверка и не полноценный GUI regression suite.

Запуск: `cargo run -p kedr-studio --locked`. Явный визуальный пример для диагностики: `--preview-results`. Функция `screenshot` и переменная `EFRAME_SCREENSHOT_TO` используются только инструментом проверки native-окна. В CI добавлены зависимости desktop-сборки Linux и запуск предпросмотра под Xvfb; результат новой ревизии еще требуется.

После начального UI добавляются безопасный сервер, драйверы, реальный каталог и запросы. Обязательные SCRAM/TLS, лимиты, протокол/параметры, отмена, обработка ошибок/отключения и macOS/Linux интеграция сохраняются в [ROADMAP](../ROADMAP.md). Первое окно или успешный screenshot не закрывают этап 6.
