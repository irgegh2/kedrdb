## Реализация

Пять crates включают настоящий `kedr-server` и нативный `kedr-studio`. Сначала переработан интерфейс после отклонения пользователем первого варианта: компактная панель, системные шрифты, плоский список таблиц, структура отдельной вкладкой, SQL с номерами строк, результаты без отдельных кнопок. Предпросмотр/данные примера не занимают обычное рабочее окно. [Решение по дизайну](../STUDIO_DESIGN.md).

Studio подключается драйвером tokio-postgres 0.7.18; TLS-адаптер 0.14.0. Есть ввод пароля без сохранения, CA и проверка имени сервера, реальные таблицы/столбцы/ограничения/индексы, выполнение всего либо выделенного SQL (Command/Ctrl+Enter), NULL, копирование ячейки, ограничения 1000 строк/2 МиБ с сообщением об усечении, код и текст ошибки, отмена, статус транзакции и переподключение. Потеря связи обнаруживается также в простое. Сеть и долгий SQL идут через ограниченную фоновую очередь; GUI не читает файлы базы. `.sql` файлы и дополнительные возможности обслуживания остаются в этапе 7.

Сервер: собственный ограниченный PostgreSQL v3.0 codec; Startup/SSL, Simple/Extended Query, параметры, binary/text типов, description без выполнения записи, ошибки с восстановлением через Sync, сохраненные порталы/PortalSuspended. Extended-цикл вне явной транзакции фиксируется на Sync, при ошибке откатывается. SCRAM-SHA-256 реализован rsasl, TLS — rustls/ring. На диске только verifier StoredKey/ServerKey; запуск по умолчанию loopback:55432, нелокальный listener требует TLS. Один admin, каталог данных с OS lock, 32 SQL-сессии, 64 сокета, таймауты/лимиты до выделения памяти, секрет отмены из OS RNG, SIGTERM/Ctrl+C и освобождение блокировки.

`SHOW TABLES/COLUMNS/INDEXES` читают собственный каталог. `SHOW KEDR STATUS` согласует API 1 и показывает I/T/E даже после ошибки. Поддерживаются OID INT4/INT8/TEXT/BOOLEAN и SMALLINT как входное представление драйвера; SMALLINT не добавляет отдельный SQL-тип таблицы. pg_catalog, все ORM/pgAdmin и полный PostgreSQL не заявляются совместимыми. Подробности/лимиты — [CONNECTIONS](../CONNECTIONS.md).

## Локальные доказательства

На macOS ARM64 уже пройдены:

- Реальный tokio-postgres: типизированный CRUD, NULL/кириллица, Read Only, BEGIN/COMMIT/ROLLBACK, abort и последующий откат, каталог, reconnect.
- Сырые пакеты: Extended pipeline с ошибкой и игнорированием дальнейшей записи до Sync, атомарный rollback цикла, PortalSuspended и продолжение.
- Отмена ожидающего блокировку запроса правильным ключом; неправильный ключ чужую сессию не отменяет; EOF откатывает незакоммиченную запись.
- Некорректные lengths/counts/UTF-8/форматы, частичный EOF и абсолютный timeout начатого frame. Пакеты ограничены до аллокации; корпус — проверка конкретных границ, не доказательство отсутствия всех ошибок протокола.
- Настоящий Worker Studio: ошибочный пароль → соединение → каталог/CRUD → транзакция/ошибка/ROLLBACK → отмена → 1102 строки с явным усечением до 1000 → потеря связи → новый сервер/reconnect.
- psql **18.2 (Homebrew)** и psycopg **3.3.2**: SCRAM + TLS verify-full, CRUD/NULL/rollback/каталог; неподходящий CA отклоняется, нелокальный listener без TLS отклоняется.
- Native окно Studio подключилось по TLS, запросило реальные четыре строки и показало их; снимок просмотрен. Закрытие окна и SIGTERM сервера завершились штатно; каталог и подтвержденные строки открылись повторно.

Локальные сырые материалы находятся в `artifacts/stage6`. Полные локальные debug/release: по 95 тестов пройдены; Clippy all-targets/all-features с запретом warnings и native/client harness пройдены. На той же ревизии Ubuntu/macOS CI подтвердили format/Clippy, по 95 debug/release тестов, миллион операций дерева и 10000 случайных точек отказа. Linux native-проверка под Xvfb использует реальные сервер, сертификат, драйвер и GUI; сам screenshot не заменяет тесты SQL/отмены/ошибок. ## Ограничения и следующий этап

Один оператор в Query/Parse. В GUI параметры `$1` не имеют отдельной панели: значения задаются в SQL, параметры проверяются через драйвер. Один писатель и ограниченная рабочая память; нет MVCC. Нет SCRAM-PLUS, ролей, COPY, произвольных OID или системных каталогов PostgreSQL. Библиотечный/OS fsync нельзя гарантированно прервать сетевым таймаутом. COMMIT после потери связи не повторяется автоматически.

На этапе 7 — согласованный backup/restore, export/import, обслуживание и `.sql` файлы Studio. Бенчмарки и выводы о скорости относятся к этапу 8; текущие проверки подтверждают поведение, а не превосходство над PostgreSQL.
