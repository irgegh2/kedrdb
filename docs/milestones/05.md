# Этап 5: таблицы и SQL

Статус: **пройден**. Linux/macOS run 37985525528 для commit 71037ceed8acedf7764a9ba50b83f81d78b73ce7 завершился success. [Сохраненные логи и результат](results/2026-10-09-stage5-ci/summary.json). Этап 4 принят в run 37981389313; [отчет](04.md).

Реализован начальный SQL-слой на Rust: tokenizer, собственная ограниченная grammar, постоянный catalog, bind имен/типов, CRUD, ADD COLUMN, PRIMARY/UNIQUE/NOT NULL, одноколоночные foreign keys на BIGINT PK, equality indices, EXPLAIN, COUNT и простой INNER JOIN. Все выполняется через session worker в одной транзакции. [Решение](../decisions/006-bounded-sql-and-transactional-catalog.md).

Локально пройдены 82 debug + 82 release tests, format/Clippy/build, 1000 typed parameter cases, конкурентные catalog/primary/secondary/FK истории с 1/2/8/32 клиентами и SIGKILL во время WAL rotation с проверкой всех acknowledgements и двух повторных recovery. [Логи и source hashes](results/2026-10-09-stage5/summary.json). Итоговый CI пройден на Linux/macOS; логи сохранены по ссылке выше. Начальный код доступен локально через `kedr sql` и `kedr sql-stream`. Сервер и GUI пока отсутствуют. Номер Rust-пакета 0.1.0 остается development.

Сверка с PostgreSQL уже обнаружила разбор `<>-1` как custom operator. Обработка обычных операторов с соседним знаком исправлена, случай сохранен в регрессионном тесте. Сохраненные неуспешные exploratory runs не считаются приемкой.

Первый расширенный прогон остановлен вручную для устранения лишнего B+ tree lookup в проверке отмены между строками. Это не расхождение SQL и не завершенная приемка. Прямые проверки cancellation/deadline сохранены и повторно проверены. Повторный полный прогон исправленной версии пройден: 1025 семантических, 33 contract cases и 100000 сгенерированных SQL запросов совпали с PostgreSQL 18.0 / psycopg 3.3.2. После 19 SIGKILL idle-сессии весь relational state повторно совпал с oracle. Всего сравнено 101181 statement (включая setup/recovery checks). [Результат и SHA-256 transcript](results/2026-10-09-stage5/sql-differential.json). Исходный JSONL остается локально в artifacts, его checksum сохранен. Это корректность на пересечении диалектов, не benchmark и не полная PostgreSQL compatibility.

В Ubuntu CI та же полная SQL campaign пройдена с PostgreSQL 16.15 и psycopg 3.1.17: 101181 сравнений; checksum transcript совпал с локальным PostgreSQL 18.0. На обеих платформах пройдены 82 debug/release tests, миллион операций дерева и 10000 crash points. Бесплатные публичные runners; timeout job 30 минут для расширенной приемки. Сервер и GUI не входят в эту приемку, они относятся к этапу 6.
