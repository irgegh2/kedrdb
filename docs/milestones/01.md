# Этап 1: Rust-основа и проверки файлового I/O

Дата: 9 октября 2026 года. Состояние: **локальная основа реализована и проверена на macOS ARM64; платформенное условие Linux пока открыто**. Этап 1 полностью пройденным не объявляется. Пользователь разрешил его начать, а также поручил сохранять важные решения в [журнале](../DECISIONS.md).

## Что реализовано

- [x] Apache 2.0: официальный LICENSE, Cargo metadata, SPDX-заголовки Rust/новых скриптов. Правообладатель и товарный знак не выдумывались.
- [x] Rust 1.94.1, edition 2024, Cargo.lock; три crates: `kedr-core`, `kedr-testkit`, `kedr` CLI. Внешних Cargo-зависимостей нет.
- [x] Типизированные ошибки KD1001–KD1009, контекст операции, запрет unsafe.
- [x] StorageIo: позиционные read/write, sync, resize, length; реальный Unix FileStorage без append/truncate.
- [x] Exact helpers: обработка short I/O/Interrupted, EOF, zero write, range overflow, некорректных byte counts backend. Ошибки не скрывают частичных изменений.
- [x] MemoryStorage: видимые/устойчивые байты и длина, лимит памяти файла, crash к последнему sync.
- [x] FaultIo: расписание по номерам вызовов, trace, short/zero/error, sync error до/после фактического сохранения.
- [x] Seeded generator и независимый sparse-byte oracle на BTreeMap.
- [x] Общая проверка write → sync → crash → read обнаруживает намеренно отсутствующий sync.
- [x] Настоящий дочерний процесс прекращается SIGKILL после sync; сохраненный префикс читается после его завершения.
- [x] CLI `doctor`, `--version`, `storage-check <directory>` с проверкой байтов после reopen и очисткой собственного файла.
- [x] Архитектурные границы: [ADR 001](../decisions/001-storage-and-failures.md). Проект формата/commit: [ADR 002](../decisions/002-format-and-transactions.md).
- [x] Workflow Linux/macOS с format, clippy, debug/release tests и CLI smoke check сохранен.

На текущем этапе данные в storage-check — тестовые байты, не таблицы базы. WAL, страницы, B+ tree, SQL, протокол, транзакции, backup и сервер не реализованы.

## Проверенная среда и результат

macOS 26.4 / aarch64-apple-darwin, Rust 1.94.1. Полный исходный набор копировался в новый временный каталог без существующего target. Проверки запускались offline с отдельным новым CARGO_TARGET_DIR; исходная папка и существующие базы пользователя не использовались как данные.

| Проверка | Результат |
|---|---|
| cargo fmt --all -- --check | Пройдена |
| clippy, все crates/targets, warnings как ошибки | Пройдена |
| Debug tests | 19 тестов, 0 ошибок |
| Release tests | 19 тестов, 0 ошибок |
| Release build из свежей копии | Пройдена |
| CLI doctor + storage-check | Пройдены, временный файл удален |
| Randomized I/O campaign | 100 seeds × 2 000 операций; сверка видимого/устойчивого состояния на каждом шаге |
| Mutation / broken-sync test | Намеренная потеря подтвержденных байтов обнаружена |
| Process crash test | Синхронизированный префикс пережил SIGKILL |
| Linux execution | **Не выполнено**, доступной среды Linux нет |

19 тестов: 4 CLI, 2 filesystem/process-crash, 13 storage-contract. Кампания на 200 000 операций входит в один из этих тестов; она запускается и в debug, и в release. Это проверка модели байтового I/O, не randomized-тесты B+ tree/SQL или показатель скорости будущей базы.

Свидетельства: [summary.json](results/2026-10-09-stage1/summary.json), [debug log](results/2026-10-09-stage1/debug-tests.txt), [release log](results/2026-10-09-stage1/release-tests.txt). В summary записаны SHA256 исходников, команды, результаты, среда и очистка временной копии. Для публикации пути временных каталогов заменены на `<temporary-snapshot>`; оригиналы сохранены локально в artifacts/publication-originals. Числа не изменялись. SHA256 workflow относится к конфигурации до добавления timeout/concurrency; Rust-исходники не менялись. Отдельного release commit пока нет.

Воспроизводимый полный запуск; output directory должен быть новым:

```sh
python3 tools/check_stage1_snapshot.py --output artifacts/stage1-rerun
```

Отдельный replay seed:

```sh
KEDR_TEST_SEED=42 cargo test -p kedr-testkit seeded_operations --locked --offline
```

## Оставшиеся условия и ограничения

- [ ] Получить и сохранить успешный Linux run. Сохраненный workflow сам по себе не подтверждает работу CI; удаленный запуск пока не выполнялся.
- [ ] Перед реализацией страниц уточнить бинарные codecs superblock, ключей/узлов, каталога и free list. ADR 002 задает начальные ограничения и порядок, не готовую совместимость файлов.
- [ ] Перед WAL/recovery расширить модель: сохранность произвольной части несинхронизированных writes, torn writes, несколько файлов и directory metadata. Сейчас MemoryStorage теряет все изменения после последнего sync целиком.
- [ ] Перед транзакциями проверить конкурентные истории, лимиты write set и поведение commit/cancellation. Один писатель остается кандидатом, пригодность для целевого benchmark не доказана.

SIGKILL не проверяет потерю питания. Успех file.sync_all в этой среде не объявляет macOS production-платформой. В тестовом trace память растет по числу вызовов; harness предназначен для ограниченных тестов, не production workload.

## Решение о дальнейшем движении

Основа позволяет проектировать и реализовывать страницы этапа 2. В текущей работе реализация этапа 2 не начата. Полное закрытие этапа 1 ожидает Linux-свидетельство; оставшиеся требования к recovery выполняются на своих этапах. Рыночные вопросы этапа 0, бренд, спрос и пилоты остаются открытыми.
