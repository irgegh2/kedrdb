# Этап 3: WAL и recovery

Дата: 9 октября 2026 года. Статус: **этап пройден; начат этап 4**. После приемки сразу начинается этап 4 по D020, без нового подтверждения пользователя.

## Реализовано

- Полные PAGE_IMAGE/COMMIT records, UUID, LSN, transaction ID, CRC32C и ограниченный разбор сегмента.
- Приватный write set поверх дерева: rollback/Drop, aborted после ошибки, отсутствие записи в исходный файл при eviction.
- Устойчивый WAL commit до изменения data, KD3002/poison при неопределенном исходе, идемпотентный redo.
- Metadata v2 с WAL protection и LSN; проверка полного WAL до изменения исходного файла; запрет восстановления старого префикса поверх более новой истории.
- Каталог базы, неизменяемая identity, process ownership, синхронизация имен, checkpoint/rotation/pruning с безопасным порядком.
- CLI `create-db`, `put/get/delete/integrity-check` для каталога и `checkpoint`. Это ключи/значения, еще не SQL-таблицы.
- Детерминированные отказы commit, recovery и checkpoint; двухфайловый симулятор torn/reordered persistence; реальный дочерний процесс SIGKILL с acknowledgement oracle.

Полный corrupt WAL tail отклоняется с диагностикой; такие случаи в кампании считаются отдельно от успешного recovery.
