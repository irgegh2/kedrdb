# Этап 7: резервные копии, перенос и обслуживание

10 октября 2026. Статус: реализация и локальные проверки; облачная приемка еще впереди. Порядок пользователя соблюден: сначала ядро/CLI/сервер, затем Studio. Пакеты остаются development 0.1.0.

## Реализовано

- Offline backup под эксклюзивным владельцем: checkpoint, identity/data/пустой WAL, manifest v1 последним, SHA-256/длины/форматы/LSN. Verify без изменения backup; restore только новый путь, карантин до проверки.
- Потоковый canonical SQL export/import: типы/NULL/Unicode/quotes/границы целых, пользовательские индексы, порядок FK, self-reference циклы. Private importer временно откладывает FK только в закрытом target, обычный SQL сохраняет немедленные ограничения.
- Возобновление после SIGKILL: оператор и ordinal в одной транзакции, неизменный SHA job, отсутствие повторных строк. Полная прямая сверка канонических байтов схемы/значений, physical integrity/checkpoint перед публикацией. Raw KV и произвольный dump не принимаются.
- PostgreSQL adapter на Python для инструментов обслуживания (ядро, сервер и Studio на Rust): read-only preflight; остановка всех писателей/DDL по явной подготовке пользователя; SHARE locks до первого SELECT snapshot; один REPEATABLE READ; приватный завершенный snapshot, durable manifest, offline resume без нового source snapshot, карантин и полная сверка.
- SHOW KEDR METRICS: queries/errors, фиксированные histogram percentile upper bounds, соединения/auth, активные sessions/locks, storage bytes/WAL/fsync/checkpoint, RSS/disk. JSON stderr logs без SQL/параметров/секретов. Offline diagnostic JSON только технические metadata.
- Studio: системные open/save `.sql`, ограниченный UTF-8 и atomic save; ошибки и сохранение текущего текста при failed open; dirty document confirmation; refresh каталога после commented DDL и COMMIT/ROLLBACK. Настоящий SQL/типизированный каталог/NULL/reconnect остаются через сетевой клиент.
- [Эксплуатационные инструкции](../OPERATIONS.md), [политика формата](../FORMAT_POLICY.md), [точные ограничения мигратора](../MIGRATION.md), [шаблон независимой приемки](../PILOT_MAINTENANCE.md).

## Уже проверено локально

- Core и CLI: roundtrip SQL с экстремальными числами, NULL, кириллицей/emoji, кавычками/переносами/псевдо-footer внутри TEXT, self-FK; восстановленная physical data.kdr совпадает; поврежденные/hash/version/path/symlink/missing WAL отклоняются; существующий target и живой владелец сохраняются.
- Настоящий SIGKILL после durable progress, запрет normal клиента, changed-source rejection, resume и точное совпадение итогового export.
- SHOW METRICS через binary/simple protocol во время другого writer transaction без ожидания его lock; есть fsync/WAL и ошибки запроса.
- PostgreSQL 18.2 / psycopg 3.3.2: 3 таблицы, 5 граничных строк, source unchanged, NUMERIC rejected до создания target, SHARE lock blocks writer, backup/restore полная сверка, mismatch при равном count оставляет migration закрытой.
- Завершенный format открыт старым stage6 binary, old binary записывает новую строку, новый binary читает ее. Reference binary SHA-256: `92ac725759efd82b6615f415a6ca0936b335477e393a199a86f23278c3eae964`.

Это проверка корректности, не benchmark скорости. Нельзя экстраполировать 224 мс snapshot пяти строк на реальные объемы. Номер тестов/итог CI и native UI evidence будут добавлены после завершения проверок точного commit.
