# ADR 007: ограниченный протокол и клиент Studio

Статус: реализовано, приемка конкретной ревизии в отчете этапа 6. 10 октября 2026.

Вместо обещания полной совместимости PostgreSQL реализуем выбранный v3.0 wire-контракт и проверяем обычные psql/tokio-postgres/psycopg. Входная длина проверяется до выделения буфера; имена, count, порталы, память и время ограничены. Свой codec отвечает только за формат/состояния протокола; криптографию выполняют rsasl/rustls/ring. В verifier сохраняем StoredKey и ServerKey, не SaltedPassword. Проверяем Validation, не только Finished. Нелокальный listener принимает Startup только после TLS.

Parse/Describe связывает SQL без исполнения. BEGIN/COMMIT/ROLLBACK можно подготовить после abort, иначе драйверный ROLLBACK оказался бы невозможен. Extended-цикл имеет собственную неявную транзакцию до Sync; ошибка игнорирует последующие команды и откатывает этот цикл, сохраняя abort явной транзакции. Неопределенный результат COMMIT не повторяем.

Studio использует настоящий tokio-postgres в отдельном Worker с одной незавершенной операцией. Результат ограничивается при сохранении в GUI, поток ответа дренируется; усечение показывается. Отмена использует CancelRequest, не закрытие чужих соединений. Собственный каталог не маскируется под pg_catalog. Версия API и транзакционный статус согласуются через SHOW KEDR STATUS; этот административный endpoint может сообщить статус abort без выполнения SQL ядра.

API 1 закладывает независимое обновление клиента/сервера, но широкая матрица будущих версий не считается проверенной. Пока продукт alpha 0.1.0, контракт может уточняться до его фиксации в 1.0. Полная изоляция, роли, SCRAM-PLUS и все OID — будущая работа, не скрытая совместимость. GUI не открывает data/WAL напрямую; .sql файлы и эксплуатационные инструменты добавляются на следующем этапе.
