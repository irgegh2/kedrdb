# ADR 002: проект формата, commit и восстановления

Дата: 9 октября 2026 года. Статус: **частичная реализация этапа 2**. Есть самостоятельный slotted-page codec версии 1 и CRC32C. Файл базы/superblock, B+ tree, WAL, checkpoint и транзакции еще не реализованы. Совместимость формата до публичного alpha не обещается.

## Начальные ограничения

- Одна база — один каталог, один владеющий процесс, один активный писатель.
- Один файл `data.kdr`; отдельные последовательные WAL-сегменты в `wal/`.
- Страница 16 КиБ; кодированная строка до 8 КиБ; overflow-строки сначала отклоняются.
- Явные фиксированные поля и little-endian. Никакой сериализации памяти Rust struct.
- CRC32C целой страницы/записи, при вычислении поле checksum заменяется нулями. CRC обнаруживает случайные повреждения, не обеспечивает криптографической защиты. Для страниц реализован portable Castagnoli CRC без внешней зависимости; стандартные контрольные векторы закреплены тестом. WAL пока не реализован.
- Версия формата отдельно от версии программы. Неизвестная версия или непонятные флаги отклоняются; обновление выполняется инструментом на копии, не автоматической перезаписью.

Версия реализованного page codec — 1. До публичного alpha она может изменяться с записью решения; никакого обещания совместимости текущих черновиков нет.

## Проект страницы данных

Первые две страницы предназначены для двух копий superblock. Они содержат magic, version, database ID, page size, generation, checkpoint LSN, metadata root и checksum. Перед реализацией фиксируем точные смещения, правила выбора пары и поведение при одинаковом generation с разным содержимым. Ни один superblock нельзя выбирать без согласованного WAL recovery.

Обычная страница имеет 64-байтовый заголовок:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 8 | magic |
| 8 | 2 | format version |
| 10 | 2 | page type |
| 12 | 2 | header size, 64 |
| 14 | 2 | reserved, zero |
| 16 | 8 | page ID |
| 24 | 8 | page LSN |
| 32 | 4 | CRC32C |
| 36 | 2 | slot count |
| 38 | 2 | free start |
| 40 | 2 | free end |
| 42 | 2 | flags |
| 44 | 20 | reserved, zero |

Таблица слотов растет от заголовка, payload — с конца страницы. Проект слота: offset:u16, length:u16, flags:u16, reserved:u16 и reserved:u64, всего 16 байт. Неиспользуемые поля нулевые. Декодер проверяет размеры, границы, перекрытия, тип страницы, ID и checksum до обращения к payload. Кодирование ключей и узлов B+ tree, каталога и free list определяется отдельной спецификацией этапа 2 до их реализации.

Реализованная часть: magic `KEDRPAGE`, type=1 (opaque records), flags заголовка=0. Slot flags=0 для живой записи и 1 для удаленной; другие значения отклоняются. Удаленный слот имеет offset/length=0, остальные reserved=0. ID>=2; decode требует ожидаемый ID, а не доверяет только прочитанному. Любой другой размер/тип/версия/неверная checksum, перекрытие, неправильная граница или ненулевые свободные байты отклоняются с KD2001.

Вставка добавляет слот с постоянным номером; запись до 8192 байт. Пустая запись допустима и отличается от удаленной. Удаление зануляет payload и сохраняет слот; пока не возвращает пространство и не уплотняет страницу. Недостаток места и слишком большая запись не меняют страницу. Codec не выделяет память в heap; он хранит 16-КиБ массив, при decode дополнительно использует ограниченную битовую карту. Checksum пересчитывается при encode. Этот primitive не обеспечивает atomic disk write, WAL durability или контроль владения файлом.

## Проект WAL

У сегмента есть собственный заголовок с database ID, format version, segment ID, начальным LSN и checksum. Нельзя применять сегмент от другой базы. Создание нового сегмента требует устойчивого файла **и записи его имени в каталоге** до подтверждения использующей его транзакции.

Запись WAL имеет 48-байтовый заголовок:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 8 | magic |
| 8 | 2 | format version |
| 10 | 2 | record type |
| 12 | 4 | header size, 48 |
| 16 | 4 | total record length |
| 20 | 4 | flags |
| 24 | 8 | LSN |
| 32 | 8 | transaction ID |
| 40 | 4 | CRC32C |
| 44 | 4 | reserved, zero |

PAGE_IMAGE несет page ID и полный образ страницы. COMMIT связывает transaction ID, диапазон LSN и число образов, чтобы recovery не принимал неполный набор. Предел размера записи проверяется до allocation; предел всего write set определяется бюджетом транзакции. LSN — монотонная логическая позиция, не адрес Rust-объекта. Точные COMMIT/segment payload, переполнение счетчиков, границы сегментов и обработку длин задаем до реализации WAL в этапе 3.

## Видимость и commit

Начальный кандидат изоляции: глобальная RW-блокировка. Read-only транзакции удерживают shared lock; изменяющая транзакция удерживает exclusive lock. Upgrade read-only в запись запрещен. Отдельные autocommit-команды — отдельные транзакции. Это простая отправная точка; способность выиграть SMALL_OLTP_V1 проверяется измерениями, и MVCC может понадобиться до 1.0.

Писатель меняет только приватные страницы. Неподтвержденные страницы не могут попасть в data file (**no-steal**). Индексы и каталог входят в тот же набор. Ограничения строк/FK/unique проверяются атомарно с записью.

Порядок commit:

1. Сформировать и проверить полный приватный набор; лимиты проверяются до durable point.
2. Записать PAGE_IMAGE и COMMIT в WAL с проверяемыми границами.
3. Успешно выполнить sync нужных сегментов и directory metadata.
4. Опубликовать уже подтвержденные страницы без новых потенциально падающих allocations. Если публикация не удается, прекращаем работу и восстанавливаемся; не возвращаем rollback для durable commit.
5. Освободить блокировку и отправить успех клиенту.

Ответ можно потерять после durable point. Поэтому disconnect не означает rollback; клиентские операции должны допускать проверяемый повтор. При ошибке записи/синхронизации WAL не продолжаем записывать поверх неоднозначного хвоста: база переходит в состояние recovery-required. На диске могла оказаться подтвержденная транзакция, даже если клиент получил ошибку. Ошибка до записи WAL может безопасно откатить приватные изменения.

## Checkpoint и recovery

Checkpoint проходит под границей согласованного состояния: завершить необходимые WAL sync, записать подтвержденные data pages, выполнить data sync, затем записать неактивную копию metadata с новым generation и checkpoint LSN, синхронизировать ее. Только после этого удалять ненужные WAL-сегменты и синхронизировать каталог. Backup может удерживать сегменты дольше.

Recovery проверяет обе metadata copies и WAL, собирает только полные COMMIT-группы и применяет полные образы страниц. Повтор recovery должен быть идемпотентным. Нельзя слепо доверять page LSN на странице с неверной checksum. Неполный последний хвост отличается от повреждения внутри ожидаемой устойчивой истории; сомнительное содержимое не пропускается молча. Выбор границы хвоста и правила повреждения — отдельные обязательные тесты этапа 3.

Это последовательность будущей реализации, а не уже подтвержденная гарантия. До ее принятия нужны точные payload/metadata codecs, ограниченный cache/write set, тесты частичной сохранности, нескольких файлов, directory sync и повторного падения при recovery. Страница/дерево реализуются в этапе 2; durable transactions — в этапах 3–4.
