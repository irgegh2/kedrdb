# ADR 006: ограниченный SQL и транзакционный каталог

Статус: реализуется на этапе 5, приемка еще не завершена.

Используем `sqlparser = 0.63.0` (Apache-2.0) для PostgreSQL tokenizer, а поддерживаемую грамматику разбираем собственным небольшим parser. Общий AST большого SQL-парсера содержит намного больше конструкций, чем состав MVP; каждую оставшуюся конструкцию явно отклоняем. Неподдерживаемые clauses не игнорируются. `default-features = false`, только `std`; транзитивно используется `log`. Cargo.lock закрепляет версии, CI выполняет fetch перед offline checks. [Исходники библиотеки](https://github.com/apache/datafusion-sqlparser-rs), [документация](https://docs.rs/sqlparser/0.63.0/sqlparser/).

Parser ограничивает SQL 64 КиБ, 4096 токенами, 32 уровнями вложения и 256 узлами выражений на statement. Ключевые слова без кавычек и quoted identifiers проверяются отдельно; словарь зарезервированных имен сверяется с PostgreSQL 18 `pg_get_keywords()`. Обычные строки не используют backslash escapes; E-строки, dollar quoting и custom operators не входят в диалект. Пробел перед унарным знаком после обычного оператора не обязателен.

Каталог и строки находятся в том же B+ tree и том же private write set, что WAL-transactions:

| Ключ | Назначение |
|---|---|
| `01` | SQL marker KEDRSQL1 и следующий table id |
| `10 + UTF-8(name)` | Версионированный schema record KEDRSCH1 |
| `20 + table-id BE + ordered BIGINT PK` | Строка, явный row codec |
| `30 + table-id BE + index-id BE + value/PK` | Вторичный индекс; значение содержит BIGINT PK LE |

Table ids монотонно выделяются внутри транзакции. DDL rollback отменяет каталог, счетчик, строки и индексы вместе. Не преобразуем существующий raw key/value store в SQL автоматически. SQL table содержит ровно один обязательный BIGINT primary key. Foreign key ссылается на один BIGINT primary key; UNIQUE реализуется вторичным индексом с отличимым PK, NULL допускает несколько строк. Простое ADD nullable column сохраняет старые строки: отсутствующий хвост декодируется как NULL.

Bind имен и типов выполняется до обхода строк, включая пустую таблицу и LIMIT 0. Parameters передаются отдельно; типы значений проверяются, числа не превращаются в строки автоматически. Предикаты используют трехзначную логику. При сравнении чисел допускается INT/BIGINT, при присваивании сужение проверяет диапазон. TEXT сравнивается по UTF-8 bytes, поэтому oracle использует C locale.

Одна SQL-команда выполняется целиком внутри worker сессии: idle timeout применяется между командами; lifetime/cancel проверяются при чтении и между строками. Ошибка aborts явную транзакцию до ROLLBACK. Autocommit не публикует частичную команду. Foreign keys проверяются по конечному состоянию команды (включая multi-row self reference), UNIQUE — при изменении индекса. Внешние ссылки NO ACTION не являются CASCADE.

Начальный planner выбирает primary equality lookup, secondary equality/IS NULL lookup либо full scan. EXPLAIN сообщает действительно выбранный путь. INNER JOIN использует потоковый nested loop и не загружает целую базу в RAM. COUNT потоковый; сортировка, результат и набор строк UPDATE/DELETE ограничены. При превышении лимита — ошибка, без неограниченного роста памяти. Оптимизация range/joins, внешняя сортировка и MVCC потребуют отдельной реализации и измерений.

Приемка: регрессионные тесты, минимум 1000 параметризованных семантических сценариев и 100000 сгенерированных SQL запросов с независимым PostgreSQL oracle; DDL/индексы/foreign keys/rollback, reopen и SIGKILL. Сравнение корректности не доказывает сетевую совместимость или лидерство по скорости.
